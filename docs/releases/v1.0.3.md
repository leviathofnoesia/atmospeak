# Atmospeak v1.0.3

Patch release: finish the 1.0.2 release→paste work. The 1.0.2 preview-paste fix
itself is intact and shipped — this release removes the paste-path costs that
rode in with the security/UX work bundled into the same pull request, and
re-arms a fallback gate that had quietly become a no-op.

## Fixes

- **Polish no longer blocks a paste it does not change.** Since 1.0.2, remote
  OpenAI-compatible polish is copy-only: the polished text is stored in history
  but the cleaned ASR text is what gets injected. The pipeline still waited on
  that request (up to `AUTO_POLISH_TIMEOUT`, 750 ms) before injecting, then
  discarded the result. Copy-only providers are now polished **after** inject.
  Local providers (Bundled, Ollama) are unchanged: they still paste polished
  output, so they still wait for it.
- **Preview paste no longer loads history to read two booleans.** The fast path
  called the full `snapshot()` — settings, dictionary, snippets, the last 100
  transcripts and their stats — between mic stop and Ctrl+V, to read
  `auto_inject`, `restore_clipboard`, and the model id. It now loads settings
  only. The live hypothesis was already cleaned with the dictionary and snippets
  frozen at listen start, so nothing else was needed.
- **The streaming-drop gate actually runs again.** "Material streaming loss
  forces Final" has been documented since 1.0.0, but the check read
  `captured.streaming_frames_dropped`, which is zero until `finalize_capture` —
  and preview paste runs before finalize on purpose. It read 0 on every
  release, so drop-damaged previews were pasted. The decision now reads the live
  counter, plus a sticky delivery flag the streaming writer publishes the
  instant `send_audio` fails — the frames lost with it are only counted once
  that writer drains, which is after preview paste has already injected, so a
  count alone would arrive too late to stop a truncated hypothesis.
- **Stage clock stops at paste on the fallback path too.** `totalMs` previously
  included post-inject work on that path; it now ends at inject, matching the
  preview path, so reported release→paste is the real number.

## Removed

- `LivePasteSnapshot::covers_duration` and `PREVIEW_COVERAGE_SLACK_MS`, dead
  since 1.0.2 removed the coverage gate. `covered_through_ms` stays as metrics.

## What happened in 1.0.2

The latency fix (`c7c6955`) removed the wall-clock coverage gate and is present
in `main` exactly as written — the merge of #17 is byte-identical to the branch
tip, and `v1.0.2` tags that merge. Nothing was dropped.

What did happen is that #17 also swept in an unrelated working tree as a single
commit (`da59d8e`, "Fold in WIP: …"): five security workstreams plus a Settings
redesign, 1 477 insertions across 31 files, landed under a title that reads as a
latency hotfix. Two of the four items above came in with that WIP; the other two
were older and stayed invisible because the surrounding measurements were taken
on a fresh profile, where an empty history makes `snapshot()` free and no
release ever drops frames.

## Measured

Release→paste on the preview path is unchanged in the common case (~20–26 ms
`totalMs`, `asr` 0). What changes:

| Path | Before | After |
| --- | ---: | ---: |
| Fallback paste, copy-only polish provider | + up to 750 ms before inject | 0 ms before inject |
| Preview paste, 100-row history | full snapshot + stats before inject | settings row only |
| Preview paste, > 240 ms of dropped frames | pasted anyway (gate read 0) | falls through to Final |

## Upgrade

Install over 1.0.2. No migration. Settings, history, and dictionary are
unchanged.
